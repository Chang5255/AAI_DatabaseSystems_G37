Two things to notice

The account is recorded. changed_by comes from SESSION_USER(), so a change made in MySQL Workbench as root is logged just like one made by the web application as inf2003. An audit rule written in Python would only have caught the second one. (CURRENT_USER() would have been wrong here: inside a trigger it returns the trigger's definer, so every row would say root.)

There is a hole, and it is not ours. MySQL does not fire triggers for rows removed by a foreign-key action, so the ratings deleted by ON DELETE CASCADE when a user is deleted never reach this table. Deleting a user through the application reports that gap instead of hiding it; closing it properly would mean deleting the ratings explicitly before deleting the user.
